# Prioritized Remediation Roadmap

This roadmap applies if discovery substantiates the illustrative findings. Owners and dates require management approval.

| Horizon | Action | Accountable owner | Completion evidence / measure |
|---|---|---|---|
| 0–30 days | Require trusted-source callback and dual approval for vendor/bank changes | CFO | 100% sampled changes show verification and approval |
| 0–30 days | Inventory all privileged, emergency, service, guest, and MSP identities | IT owner | Reconciled register with owner and purpose |
| 0–30 days | Validate MFA for admins, workforce, VPN, and MSP; remediate exceptions | IT owner / MSP | Export shows approved coverage and documented exceptions |
| 0–30 days | Test restoration of one critical finance/project data set | IT / Finance / MSP | Successful timed restore; gaps and RTO/RPO recorded |
| 0–30 days | Publish incident and payment-fraud escalation contacts | Executive sponsor | Approved call tree tested in tabletop |
| 31–90 days | Implement risk-based Conditional Access and dedicated admin identities | IT / MSP | Policies tested; legacy paths blocked or exception-approved |
| 31–90 days | Formalize joiner/mover/leaver and quarterly access reviews | HR / IT / app owners | SLA and sample completion metrics |
| 31–90 days | Restrict external sharing and execute project-closeout access reviews | Project Ops / IT | External-user/link baseline reduced and owner-certified |
| 31–90 days | Constrain, log, and contractually govern MSP access | Management / IT | Named accounts, review, logs, revocation test, agreed duties |
| 31–90 days | Approve critical-system RTO/RPO and backup coverage | Management / owners | Signed impact analysis and coverage map |
| 3–6 months | Establish endpoint/mobile baseline for inventory, EDR, encryption, patching, privilege, MDM/MAM | IT / MSP | Coverage KPIs and exception register |
| 3–6 months | Centralize priority identity, email, endpoint, firewall, and VPN monitoring | IT / MSP | Logging matrix, retention, alert tests, response SLAs |
| 3–6 months | Implement resilient backup design and recurring restore tests | IT / MSP / owners | Isolated/immutable copies and quarterly test success |
| 6–12 months | Mature third-party inventory, due diligence, and contract requirements | Management / procurement | Critical vendor register and review completion |
| 6–12 months | Run BEC/ransomware/hurricane tabletop and targeted awareness | Management / Finance / IT | Exercise after-action report and closed actions |

## Prioritization rationale

Payment and privileged-identity controls lead because they reduce plausible catastrophic loss quickly. Recovery and incident coordination follow in parallel because prevention can fail and South Florida operations face both cyber and regional-disruption scenarios. Governance, monitoring, and third-party maturity sustain those gains.

## Closure rule

An action is not closed when a product is purchased or policy is drafted. Closure requires implemented design, representative operating evidence, exception disposition, owner acceptance, and risk re-scoring.
